# アーキテクチャ

2026 年 11 月時点の実装の説明です。初期の設計は [design.md](design.md) にありますが、回答の生成方式などは現在と異なります。

この文書に書くのは、実装されていてテストがあるものだけです。数値は、コードの定数か、実アプリで測った値です。測っていないことは「未確認」と書きます。

## 1. 全体像

Electron のアプリです。3 つのプロセスに分かれ、外部との通信はすべて Main プロセスが行います。

| プロセス | 役割                                                      | 主なファイル               |
| -------- | --------------------------------------------------------- | -------------------------- |
| Renderer | 画面（React）。ネットワークには出ない                     | `src/renderer/App.tsx`     |
| Preload  | Renderer に公開する API を決める                          | `src/preload/preload.ts`   |
| Main     | IPC の受付、質問の実行、設定の保存、MOOCs と API への通信 | `src/main/ipc-handlers.ts` |

Main の外側には、次の 3 つがあります。

- **INIAD API**（OpenAI 互換の Chat Completions）：`src/main/services/api-client.ts` が呼びます。
- **MOOCs 用の MCP サーバー**：子プロセスとして起動し、Playwright のブラウザーで MOOCs を操作します。`src/main/services/mcp-client.ts` が接続します。
- **Web 検索**（DuckDuckGo Instant Answer API）：`src/main/services/web-search-client.ts`。

## 2. 質問 1 件の流れ

1. Renderer が `chat:send` を呼びます。
2. `src/main/ipc-handlers.ts` が、呼び出し元と入力を検証します（§6.1）。
3. `src/main/chat-runner.ts` の `ChatRunner` が実行します。必要なら MCP に接続し、過去に読んだ資料から質問に関係するものを選びます。
4. `src/main/services/chat-agent.ts` の `ChatAgent` がループを回します（§3）。
5. 回答が確定したら、質問と回答をまとめて履歴に保存し、読んだ資料を保存します。
6. 回答を Renderer に返します。

失敗とキャンセルでは、保存するものが違います。

| 終わり方       | 履歴             | 読んだ資料                       |
| -------------- | ---------------- | -------------------------------- |
| 回答が返った   | 質問と回答を保存 | 保存                             |
| 途中で失敗した | 保存しない       | **保存する**（次の質問で使える） |
| キャンセルした | 保存しない       | 保存しない                       |

履歴と資料は Main のメモリにだけあります（`src/main/services/in-memory-store.ts`）。アプリを終了すると消えます。資料の本文は Renderer には渡さず、題名と URL だけを渡します。

## 3. エージェントのループ

`ChatAgent` は、AI に問い合わせ、返ってきたツール呼び出しを実行し、結果を付けてもう一度問い合わせる、を繰り返します。AI がツールを呼ばずに本文を返したら、それが回答です。

ループ自体は判断をしません。何を許すかは policy に尋ね（§4）、何を送るかは文脈の整形に任せ（§5）、起きたことは trace として出します（§7）。

| 部品           | ファイル                                      | 役割                               |
| -------------- | --------------------------------------------- | ---------------------------------- |
| ループ         | `src/main/services/chat-agent.ts`             | 問い合わせとツール実行の繰り返し   |
| 方針           | `src/main/services/agent-run-policy.ts`       | 上限、ツールの可否、予算           |
| 文脈の整形     | `src/main/services/agent-api-messages.ts`     | ツール結果を予算内に収める         |
| 履歴の選択     | `src/main/services/agent-history.ts`          | 送る会話履歴を選ぶ                 |
| 過去の資料     | `src/main/services/material-prompt.ts`        | 資料を参照データとして整形する     |
| 境界           | `src/main/services/untrusted-reference.ts`    | 信頼できない文を囲む               |
| 引用           | `src/main/services/citation-merge.ts`         | 同じ URL の引用をまとめる          |
| ツール定義     | `src/main/services/moocs-tool-definitions.ts` | AI に渡すツールの一覧              |
| ツール実行     | `src/main/services/moocs-tool-executor.ts`    | 引数の検証と実行                   |
| ページ読み取り | `src/main/services/moocs-page-reader.ts`      | スライドと HTML ページの本文を取る |
| 記録           | `src/main/services/agent-trace.ts`            | イベントの型と秘匿処理             |

AI に渡すツールは 10 個です。MOOCs 用が 9 個（ログイン、コース一覧、ページ移動、講義一覧、資料一覧、資料の読み取り、スライドの展開、ページ内容、Google ログイン）と、`web_search` です。どれも読み取りだけで、課題の提出などの書き込みはできません。

### 回答の終わり方

API の `finish_reason` を見て、最後まで書かれたかどうかを区別します。

- `length`（出力の上限）や `content_filter` で終わった回答は、本文を書き換えずに「途中まで」の印を付けます。印は履歴にも残り、その回答の下に表示されます。
- 本文が空のときは、理由つきのエラーにします。

## 4. 方針（policy）

`AgentRunPolicy` が、1 回の実行で何を許すかを決めます。実行ごとに 1 つ作られ、状態はその中だけにあります。

| 決めること             | 規則                                                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 問い合わせの回数       | 最大 10 回。最後の 2 回はツールを渡さず、回答だけを求める                                                         |
| ツール呼び出しの回数   | 実行するのは最大 12 回。超えた呼び出しは実行せずに断る                                                            |
| `web_search`           | 1 回の実行で 1 回まで。MOOCs のツールを使ったあとと、過去の資料やシラバスのヒントがプロンプトにあるときは使えない |
| 同じ呼び出しの繰り返し | 2 回までは実行し、3 回目から断る。ログインすると数え直す                                                          |
| 時間の予算             | 150 秒を超えたら、次の問い合わせでツールを渡さずに回答させる                                                      |
| トークンの予算         | 入力トークンの合計が 60,000 に達したら、同じく回答させる。API が usage を返さない実行では使わない                 |

補足です。

- 呼び出しは、許可した時点（実行の前）で数えます。失敗した呼び出しも 1 回に数え、失敗した MOOCs の呼び出しのあとも `web_search` は使えなくなります。
- 断った呼び出しは回数に数えません。
- 予算は問い合わせの前にだけ確かめます。実行中のツールは止めないので、それまでに読んだ資料は回答に使われます。超えても例外やキャンセルにはなりません。
- 時間とトークンの上限は、実アプリの記録 30 回から決めました。その 30 回で予算に達した実行はなく、同じ呼び出しの 3 回目に達した実行もありません。この 2 つは通常の質問には影響しない歯止めです。

## 5. 文脈の予算

AI に送るツール結果は、合計 12,000 字までです（`agent-api-messages.ts`）。残す順は次のとおりです。

1. 直近 2 件（種類を問わない）
2. それより前の、資料の本文を含む結果（新しい順）
3. それより前の一覧やページ移動の結果（新しい順。2,500 字まで）

入らなかった資料は、本文を省いて題名と URL だけを残します。要約はしません。ツール呼び出しとその結果の対応は、必ず残します。

そのほかの上限です。

| 対象                        | 上限                         |
| --------------------------- | ---------------------------- |
| ツール結果 1 件             | 4,000 字                     |
| 会話履歴                    | 直近 6 ターン、合計 2,000 字 |
| 保存する資料                | 30 件、1 件 4,000 字         |
| 過去の資料から 1 回に渡す分 | 3 件、合計 4,500 字          |
| 回答の長さ                  | 2,048 トークン               |

## 6. 信頼の境界

### 6.1 Renderer と Main のあいだ

- IPC のハンドラーは、呼び出し元が信頼するウィンドウのメインフレームであることを確かめます。サブフレームと、破棄されたウィンドウは拒否します。
- 入力は `src/main/ipc-validation.ts` で検証します。引数を取らないチャネルに引数が付いていれば拒否します。
- Renderer は `sandbox`、`contextIsolation` を有効にし、CSP で外部への通信を禁じています（`connect-src 'none'`）。
- 外部の URL を開くのは、検証済みの HTTPS の URL を OS のブラウザーに渡すときだけです。

### 6.2 信頼できない文と AI のあいだ

MOOCs のページ、Web 検索の結果、過去の資料、シラバスの索引は、どれも外から来た文です。AI への指示が紛れているかもしれません。

- これらは境界のマーカーで囲んで渡します（`untrusted-reference.ts`）。中身にマーカーと同じ文字列があれば取り除くので、囲みを抜け出せません。
- 過去の資料やヒントは、システムの指示としてではなく、利用者側のメッセージとして渡します。
- 信頼できない文を読んだあとは、外へ出る手段（`web_search`）を閉じます（§4）。ページの指示に従って質問文を検索に流す、という経路を断つためです。
- MOOCs のツールが受け付ける URL は `https://moocs.iniad.org` だけです。ホスト名を解析して比べます。

### 6.3 MCP と外部のあいだ

- MCP の子プロセスに渡す環境変数は、決めた一覧と MOOCs の認証情報だけです。
- MCP のブラウザーが通信できるのは、`iniad.org` と Google のドメインだけです（`scripts/mcp-network-policy.cjs`）。
- 呼べる MCP のツールは 9 個に固定し、引数も検証します。
- 配布物の MCP ランタイムは、起動の前に SHA-256 で照合します。
- MCP が返したエラーの文は、そのまま外へ出しません。決めた分類と文面に置き換えます。例外は、スライド抽出が返す 5 種類の結果で、種類と MOOCs の URL だけを通します。
- API の URL は、送信の直前にも公式のホストであることを確かめます。

### 6.4 認証情報

API キーと MOOCs の認証情報は、OS の仕組み（Electron の `safeStorage`）で暗号化して保存します（`src/main/services/settings-store.ts`）。Renderer には値を返さず、設定済みかどうかだけを返します。

## 7. 実行の記録（trace）

ループは、6 種類のイベントを出します：`run_start`、`llm_start`、`llm_end`、`tool_start`、`tool_end`、`run_end`。`run_end` は、どの終わり方でも 1 回だけ出ます。

記録するのは、件数、長さ、時間と、決まった値だけです。

| 項目                               | 記録の仕方                                                      |
| ---------------------------------- | --------------------------------------------------------------- |
| 質問、回答、教材の本文、エラーの文 | 記録しない（長さと件数だけ）                                    |
| URL                                | MOOCs の URL のパスだけ。それ以外は「拒否した」という印だけ     |
| 検索語                             | 長さだけ                                                        |
| ツール名                           | 知っている名前だけ。それ以外は `unknown`                        |
| ツールの結果                       | 成否の種類（`ok`、`invalid_arguments`、`mcp_error` など）と長さ |
| usage                              | 数値だけ                                                        |

イベントの受け取り先（sink）は複数登録できます。1 つが例外を投げても、ほかの受け取り先と回答は止まりません。いまの受け取り先は 3 つです。

| 受け取り先 | ファイル                            | 内容                                                                |
| ---------- | ----------------------------------- | ------------------------------------------------------------------- |
| コンソール | `src/main/services/agent-trace.ts`  | 問い合わせ、ツール、終了を 1 行ずつ                                 |
| ファイル   | `src/main/services/trace-writer.ts` | `userData/traces` に 1 実行 1 ファイル（JSONL）。新しい 50 件を残す |
| 進捗表示   | `src/main/chat-progress.ts`         | 質問を送ったウィンドウにだけ、何をしているかの種類を送る            |

記録にはコースと講義回が URL のパスとして残ります。保存を止める設定はありません。

## 8. MOOCs の読み取り

`moocs_read_slide` は、URL の形でページの種類を決めます（`src/main/services/moocs-page-kind.ts`）。

- **スライドのページ**（例：`/courses/2026/XXX000/01/01`、`/courses/2026/XXX000/vod01/01`）：Google スライドの本文を取り出します。
- **それ以外**（課題解説、演習課題など）：ページの HTML を読みます。

スライドの読み取りの順です。

1. スライドの索引（`data/slides-index.json`）にあれば、それを返します。抽出はしません。
2. 質問 1 件につき 1 回、Google にログインします。INIAD のスライドは、ログインしていないと 0 枚に見えます。
3. 公開ビューアでスライドを 1 枚ずつ送り、本文を集めます。
4. スライドがない、または文字を取り出せないときは、ページの HTML を返します。取り出せなかった場合は、読み直しても変わらないことを一文で伝えます。

Google へのログインは、MCP のツールが INIAD の SSO を通して行います。ログインに失敗しても、MOOCs への接続は切りません。

MCP のツールのうち、スライドの展開、スライドの抽出、Google ログインは、パッケージへのパッチ（`patches/`）で足したものです。実物のブラウザーで動くので、自動テストはありません。

## 9. テスト

`npm test` で、ユニットテストとシナリオの再生（§10）が動きます。件数は 600 件あまりで、認証情報が必要な統合テストだけがスキップされます。CI は、PR と main への push で、lint、整形、型検査（src と tests）、`npm test` を実行します。

| 対象                               | テスト                                                                                                                     |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| ループの上限と、切れた回答         | `tests/unit/chat-agent-limits.test.ts`                                                                                     |
| ループのセキュリティ境界           | `tests/unit/chat-agent-security.test.ts`                                                                                   |
| 方針（上限、可否、繰り返し、予算） | `tests/unit/agent-run-policy.test.ts`、`tests/unit/chat-agent-budgets.test.ts`                                             |
| 文脈の予算                         | `tests/unit/agent-api-messages.test.ts`                                                                                    |
| 実行の記録と秘匿処理               | `tests/unit/agent-trace.test.ts`、`tests/unit/trace-writer.test.ts`                                                        |
| 進捗表示                           | `tests/unit/chat-progress.test.ts`                                                                                         |
| IPC の信頼境界と保存の規則         | `tests/unit/ipc-handlers.test.ts`、`tests/unit/ipc-validation.test.ts`                                                     |
| ツールの実行と結果の種類           | `tests/unit/moocs-agent-tools.test.ts`                                                                                     |
| ページの読み取り                   | `tests/unit/moocs-page-reader.test.ts`、`tests/unit/moocs-page-kind.test.ts`、`tests/unit/chat-agent-google-login.test.ts` |
| MCP の接続と境界                   | `tests/unit/mcp-client-security.test.ts`、`tests/unit/mcp-connection.test.ts`、`tests/unit/mcp-network-policy.test.ts`     |
| 設定と認証情報                     | `tests/unit/settings-store.test.ts`                                                                                        |
| シナリオの再生                     | `tests/eval/replay.test.ts`                                                                                                |

確かめ方について。

- **動作を変えない移動**（分割や切り出し）は、既存のテストを変えずに通ることを根拠にしています。
- **判定の変更**は、該当の行を 1 つずつ壊して、テストが落ちることを確かめています。ミューテーションテストのツールは使っていません。
- **Renderer には自動テストがありません。** 表示の文を決める関数だけを分けてテストし、画面は実アプリで確かめています。

## 10. 評価

2 種類あります。

- **replay**（`tests/eval/`）：AI の応答と MOOCs のページを台本で決め、本物のループに流します。8 つのシナリオがあり、CI で動きます。確かめるのはループの動きで、回答の品質は測れません（回答文は台本の文字列です）。データは合成で、実在の教材は入っていません。
- **live**（`tests/eval-live/`）：実際の API と MOOCs で質問を実行し、期待したツール、URL、語句がどれだけ満たされたかを採点します。手で実行します（`npm run eval:live`）。採点の関数は CI でテストしています。

live の評価は、まだ一度も実行していません。評価用の質問もまだありません。そのため、ここまでの変更で回答が良くなったかどうかは、分かっていません。

## 11. 分かっていること、分かっていないこと

実アプリで、1 つのコースの 1 つの質問を繰り返して測った値です。ほかの質問には当てはまらないかもしれません。

- 1 問あたり 50〜70 秒、AI への問い合わせは 7〜9 回、入力トークンは 1.8 万〜2.8 万です。
- スライド 1 件の抽出に約 15 秒かかります（29 回送る資料の場合）。
- INIAD API は、`finish_reason` と `usage` を毎回返します。
- 同じ資料を 2 回読むことが、3 回に 2 回の実行で起きています。3 回以上は記録にありません。

未確認、または未対応のことです。

- 回答の品質（§10）。
- INIAD API の入力の上限。
- Web 検索が実際に結果を返す割合。
- `npm run package` で作った配布物での動作。CI は配布物を作りません。
- 開発用の依存に、既知の脆弱性が 41 件あります。本番の依存は 0 件です。解消には electron-forge のメジャー更新が必要です。
- main のブランチ保護は設定していません。
